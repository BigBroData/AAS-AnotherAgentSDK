# AAS (AnotherAgentSDK) - Vision & Core Principles

## Суть проекта
AAS — это **не конструктор**, где разработчик мучается с выбором транспорта.  
Это **высокопроизводительный движок**, который изначально спроектирован так, чтобы обеспечивать:
- Максимальную предсказуемость
- Минимальную задержку (latency)
- Простоту разработки
- Надёжность и масштабируемость

---

## Ответ на вопрос «Что такое программирование» в контексте AAS

**Программирование** — это управление состоянием и потоком данных с минимальными накладными расходами.

Чтобы получить «правильную» программу (агент), нужно:

### 1. Убрать абстракции-посредники
Никаких тяжелых оркестраторов, сериализаций JSON на каждом шаге или лишних асинхронных переключений, если они не нужны.

### 2. Локальность данных
Состояние агента должно быть доступно мгновенно. Если слои работают в одном процессе (Bun), связь должна быть:
- Синхронной, или
- Через максимально быстрые примитивы (shared memory, direct function calls)
- **Не** через сеть/очереди по умолчанию

### 3. Детерминизм
Поведение системы должно быть полностью предсказуемым:
- Ошибка в одном слое не должна вешать всю систему
- Но и не должна требовать сложной распределенной отладки

### 4. Простота кода
Код агента должен читаться как линейная логика (как пример с кодинг-агентом), даже если под капотом происходит сложная работа.

---

## Проблема текущих фреймворков (LangChain, CrewAI, etc.)

Они добавляют огромные накладные расходы ради «гибкости», которая часто не нужна:
- Превращают простой вызов функции в сложный граф обещаний
- Сериализация данных на каждом шаге
- Лишние аллокации памяти
- Это убивает скорость и делает поведение непредсказуемым

---

## Что именно надо делать в AAS

Реализовать **ядро (Core)**, которое:

### 1. Предоставляет примитив `Layer` (Слой)
Чистая функция или класс с четким входом/выходом.

### 2. Реализует механизм `Pipeline` (Конвейер)
Максимально быстрый способ передать результат одного слоя в другой внутри процесса Bun:
- Без сетевого оверхеда
- Без лишней сериализации

### 3. Дает возможность (опционально) выносить слои в отдельные процессы/сервисы
Только если это критично. По умолчанию всё работает как единое целое для скорости.

### 4. Управляет состоянием (`State`) централизованно и эффективно
Без копирования данных туда-сюда.

---

## Идея для реализации

Вместо сложного графа с условиями, мы делаем **управляемый поток выполнения**:

1. **Agent** — контейнер состояния
2. **Layers** — обработчики
3. **Router** — простая, быстрая логика: "выполни слой А, потом, основываясь на результате, выполни Б"
4. Всё это компилируется/выполняется средой Bun в один высокооптимизированный процесс

### Опционально: свой инференс-движок
Если нужно, внедрим легкий инференс-движок:
- На C/Zig через FFI, или
- Чистый TS оптимизированный код
- Чтобы убрать задержки на вызов внешних API там, где это возможно
- Или сделать проксирование к LLM максимально прямым (streaming without buffering)

---

## Стратегия развития

**Первый шаг:** Написать прототип линейного пайплайна (как в примере с кодинг-агентом), который работает быстрее, чем любой существующий фреймворк.

**Второй шаг:** Добавить возможность ветвления, но сохраняя эту скорость.

**База:** "Super-fast linear execution", а не "Graph builder".

## Ключевые отличия от аналогов

| Характеристика | LangChain/CrewAI | n8n | **AAS** |
|----------------|------------------|-----|---------|
| Архитектура | Тяжелые абстракции | Визуальный workflow | Минималистичное ядро |
| Транспорт | JSON + async overhead | HTTP/очереди | Direct calls / shared memory |
| Скорость | Низкая | Средняя | **Максимальная** |
| Предсказуемость | Низкая | Средняя | **Высокая** |
| Порог входа | Высокий | Средний | **Низкий** |
| Гибкость | Высокая (но дорогая) | Высокая | **Разумная** |

## Цель

Найти наиболее эффективный способ соединения слоев в агентных приложениях через:
- Минимализм
- Прямое управление памятью и потоком данных
- Отсутствие скрытой магии
- Фокус на производительности и предсказуемости
